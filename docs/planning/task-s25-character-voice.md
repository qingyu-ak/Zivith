# Feature

功能名称：群聊角色感（说话像这个人）

> Status: **Implemented — 2026-09-21**。产品所有者在拍间 / 刻度 / AI 接管入库后要求收完积压 4。用已有角色卡把口吻锁住，不加心情旋钮。空卡不拦开聊；失败/取消/再进线程不另做状态。

> 所属 Journey：**D（多角色互动）** · 验收「发言逻辑自然」

> 宪法依据：产品宪法 Journey D、§8–10。世界 = `Project`。不改数据模型。不新建字段。

## User Problem

群聊里谁在说话能看清，但听起来不像那个人。楚子航和路明非会共用同一套括号动作（插兜、船舷、盯海面）和同一套讲解腔，把亲历当课上。用户怀疑要不要给男性角色加情绪/心情控件。

## User Goal

用户希望：还是这两三个人在聊，但一句听得出是谁。不新开一排心情滑杆。个性已经写在角色卡上的，上场要用。

## Entry

已有扮演 / 群聊线程。不改入口、不改顶栏。

## Main Flow

1. 组装该说话人的角色卡时，把「个性」抽成短的说话方式，放在提示词最前面。
2. 这一拍限制：一两句对白、括号动作最多一个。
3. 上一拍已经用过的括号动作，这一拍禁止再写。
4. 空拍找话题时，优先用个性/关系里的短线索，不要把长亲历讲成说明书。

## States

### Empty

角色卡没填个性：仍要求用这个人自己的话，不要书面腔、不要抄别人的动作。不因此拦截开聊。

### Loading

生成中：沿用现有思考/停止。无新控件。

### Success

同一场里两个人的句长、用词、动作不再同一个模子。

### Error

生成失败仍走现有横幅。不另做角色感错误。

### Retry

同一套重试。

### Cancel

暂停交流 / 插话 / 停止思考不变。

## Data

- 读现有 `Asset.data.personality`（角色卡「个性」）。不新建表、不加心情字段。
- 谁消费：扮演 system prompt、空拍/接管 cue。
- 改了之后：下一句生成即用；Chat / Studio 界面无新开关。不写世界。

## Cross-module Impact

扮演提示词与群聊空拍 cue。不改角色卡编辑 UI、不改记忆层、不改 Agent。

## User Control

本切片不写世界。世界变化仍走提案确认。

## Recovery

刻度回退 / 撤回该句。提示词改的是之后怎么说，不改已经说的。

## Acceptance Criteria

- [x] 提示词里说话方式在档案/亲历之前，并带上角色卡个性（有则用）
- [x] 群聊一拍：对白短、括号动作最多一个；上一拍用过的动作不再用
- [x] 空拍话题优先短个性/关系，而不是把长亲历当讲义
- [x] 不加心情 / 情绪 / 旋钮；不改数据模型；读者/你扮演规则不变
- [x] 空卡、失败、取消、再进线程不出现新的卡住状态

## Out of Scope

心情滑杆、多维情绪控件、4+ 人、会话分支、World Builder 抽取、改角色卡表单、Agent 口吻。

## Implementation Constraints

- 不改数据模型。
- 不因「感觉应该有」加控件。
- 复用现有 personality 字段与群聊节拍。

## 实现记录（2026-09-21）

| 层 | 文件 | 说明 |
|----|------|------|
| API | `character-voice.ts` | `buildVoiceLock`：个性在前；空卡仍要求用自己的话。`collectRecentStageDirections` 用去虚词后的二字对上「船舷 / 插兜」变体。群聊回复落下时最多留一个括号动作 |
| API | `roleplay-agent.ts` | system prompt「这一拍怎么说话」在档案/亲历之前；群聊每拍把近期括号动作写进口吻锁 |
| API | `group-continue.ts` / `routes/roleplay.ts` | 空拍话题优先短个性/关系；用户开口的群聊拍同样禁近期动作 |
| test | `character-voice` / `group-continue` / `roleplay-agent` | 空卡、变体去重、空池话题、用户开口拍禁动作 |

失败仍走现有横幅；取消仍走 `aborted`；口吻锁每拍从角色卡现算，再进线程没有新状态。
