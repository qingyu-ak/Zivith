# Feature

功能名称：交谈三层记忆（日志 / 重要聊天 / 检索目录）（P0-08b）

> Status: **Implemented — 2026-09-16**。聊天三层：日志 / 重要聊天 / 检索目录；窗口满了折进滚动摘要；问还记得时先检索再答。
>
> 所属 Journey：**C（第一次与角色生活）**「角色记住重要信息」；顺带 **F** 关掉再开对话还在
>
> 闭环位置：按世界时间记得（P0-08a 已完成）→ **补上中间态 + 先检索再答（本切片）** → 短期窗口与热词重载（不作为角色记忆，另开）
>
> 宪法依据：产品宪法 Journey C/F、立宪裁决「聊天与世界」「记忆」；ADR-0014「原文 → 中间 → 核心」。世界 = `Project`。

## 产品分界

扮演按世界时间读角色认知；World Builder 仍是工具/提案。本切片只修**角色交谈**的三层——上一稿只写了日志和目录，中间态被挤掉了。

```text
对话日志（L0）          全文留下，可翻、可关掉再开、可还原
        ↓ 提取重要段
重要聊天（中间态 / L1） 精简后的重要记录：人能读、能改、能忘掉
        ↓ 编目录
检索目录（L2）          更短的主题/要点索引；问「还记得」时先查这里
                        命中后再打开中间态，必要时回溯原文摘录
```

| 用户看到的 | 存什么 | 干什么 | 不是 |
|------------|--------|--------|------|
| 这次对话里的每一句 | `CreatorChatMessage` | 日志：追溯、还原 | 世界事件、角色人生 |
| 「调整记忆」里的交谈要点 | `MemoryAtom` | **中间态**：精简后的重要聊天 | 全文复读、每句归档 |
| 主题短索引（可很少露） | `MemoryCore` | **检索目录**：先搜到哪一块 | 把档案正文整段灌进角色嘴里 |
| 角色说「记得 / 不记得」 | 先查目录 → 中间态 → 原文摘录 | 再开口 | 只靠最近几轮窗口瞎编 |

不引入第二套向量库。不新建表。不把扮演做成 Agent 工具循环。

### 短期记忆、热词：不要做成第四套角色记忆

| | 是什么 | 单独成「角色记忆」吗 | 放哪 |
|--|--------|----------------------|------|
| **短期记忆** | 这一轮还能接上话：最近几句原文 + 滚动摘要 | **不**。它是这次对话的工作窗口，不是林夕的人生 | 已有 `ThreadContextState`。压缩只作用于 prompt；事实已在三层里。宪法：临时上下文不作为世界事实 |
| **热词重载** | 语音把「林夕」「旧码头」听准；世界改名后索引跟上 | **不**。它是从正式名称派生的识别表，角色不会「记得热词」 | 已有热词文件，来源是实体名/事件标题（ADR-0017）。世界名变了再生成。跟 Agent/语音走，不进「调整记忆」 |

Agent 自己的工作记忆、工具轨迹、热词重载仍是 **Agent 运行时**，和角色三层分开；本切片不做。

### 上下文满了（长期聊天）

压缩只作用于**这一轮塞进模型的窗口**，不删日志、不改中间态、不改世界。

```text
每一轮实际给模型的只有：
  ① 角色认知（这个时间点的卡 / 亲历 / 关系）
  ② 短期窗口：滚动摘要 + 最近 K 句原文
  ③ 本轮检索：目录 → 中间态 → 必要时原文摘录
  ④ 当前这句话
```

满了之后：

```text
窗口超出预算
    ↓
最旧的几句退出 prompt（数据库里的对话日志不动）
    ↓
退出的内容折进滚动摘要（措辞可损，事实已在中间态/目录里）
    ↓
摘要自己过长 → 再压一次，保持上限，不当档案越积越长
    ↓
用户问很早以前的事 → 不靠窗口，走检索目录
```

原则：**压缩有损于措辞，无损于事实。** 用户向上翻仍是全文。角色接话靠窗口；「还记得吗」靠目录。

现状缺口：World Builder 淘汰后会写入滚动摘要；扮演目前只截最近几句，**没有把淘汰段折进摘要**，聊长了旧对白从 prompt 里消失且补不回来。本切片要补上这一步。不把滚动摘要画进「调整记忆」。

## User Problem

已经能和角色说话，全文也落在对话里，但：

- 三层被收成「日志 + 目录」，没有可读的中间态；「调整记忆」要么摊开整句对白，要么只剩碎片要点。
- 窗口一压缩，旧对话只剩摘要；问「你还记得……」「你什么时候做了……」时，角色搜不到目录，也回不到重要聊天和原文。
- 短期窗口和热词如果再当成「记忆」展示，会和角色人生搅在一起。

## User Goal

1. 聊天全文始终留在这次对话记录里；关掉再开还能看见、还能当日志用。
2. 「调整记忆」展示 **精简后的重要聊天（中间态）** + 这个时间点的亲历；不把日志铺进去，也不把热词/短期窗口画成记忆。
3. 用户问「还记得吗」或「你什么时候做了什么」：角色先查检索目录，命中后再看中间态和原文摘录，再回答；搜不到就以角色身份说记不清，不编造。
4. 聊很长、窗口满了：旧句退出 prompt，折进滚动摘要；日志仍在；问很早的事走检索，不靠窗口硬塞。
5. 检索仍受当前世界时间约束；世界事件仍要确认才进时间线。

成功时用户知道：对话是可以翻的日志；记忆是精简过的重要聊天；目录用来先查再答。

## Entry

- 现有扮演对话区（日志本身）。
- 现有「调整记忆」（中间态 + 亲历）。
- 不新开日志浏览器，不新开热词/短期记忆设置页。

## Main Flow

```text
已有世界、已有角色、已进入扮演（当前锚点 T）
    ↓
用户说话（含「还记得……」「你当时做了……」）
    ↓
1. 全文写入本对话日志（L0，不删）
2. 从全文提取重要段 → 中间态（精简记录，不是整句复读）
3. 中间态编进检索目录（主题/短索引）
4. 按这句话检索：
     · 先查该角色、不超过 T 的目录
     · 命中后打开对应中间态
     · 需要还原时用 sourceMessageId 取原文短摘录
5. 角色只根据：当前认知 + 目录/中间态/摘录 回答
    ↓
用户打开「调整记忆」→ 看到重要聊天和亲历，不是全文、不是热词
用户向上翻对话 → 看到完整日志
当下几句能接上 → 靠短期窗口，不另存一套记忆
```

## States

### Empty

- 还没说过话：对话空态说明「全文会留在这次对话里；重要的会收成精简记录；问还记得时先查目录再答。」
- 这个时间点没有亲历、没有重要聊天：「调整记忆」保持短空态，不造条目。

### Loading

- 发送中：沿用现有「想了一下」；禁止连点。
- 打开「调整记忆」：沿用现有加载文案。

### Success

- 关掉再开：对话全文还在（Journey F）。
- 「调整记忆」是可读的精简记录，不是聊天复读。
- 问到日志/中间态里确有的事：下一句能对上，不否认刚谈过的内容（仍不得突破 T）。
- 问到都没有的事：角色表示记不清 / 没印象，不编细节。

### Error

- 「没能更新记忆 / 没能检索。请再试一次。」草稿保留；日志已写入的不回滚。

### Retry

- 同一句再问一次；检索再走一遍。

### Cancel

- 关掉「调整记忆」、拒绝世界提案：不写原子、不写世界。对话日志不动。

## Data

| 数据 | 本切片怎么用 |
|------|----------------|
| `CreatorChatMessage`（日志） | 全文不删；命中时取短摘录 |
| `MemoryAtom`（中间态） | 精简后的重要聊天；人可读可改可忘掉；`sourceMessageId` 回溯原文 |
| `MemoryCore`（检索目录） | 主题短索引，用来先搜；扮演不把全书档案正文整段当对白 |
| `ThreadContextState`（短期窗口） | 最近原文 + 滚动摘要；满了淘汰旧句并折进摘要；**不进「调整记忆」、不写世界** |
| 热词文件 | 从角色名/地点名/事件标题派生；**不是记忆**；本切片不重载 |
| `WorldEvent` / `Relationship` | 亲历与认识谁；问「什么时候做了」优先用已确认的亲历 |
| 提案 pending | 世界变化仍确认；本切片不扩大自动写世界 |

不新建表。不引入 Chroma / Milvus / Redis。不把 L0 做成关会话即删。不为短期记忆或热词新建记忆表。

## Cross-module Impact

| 模块 | 变化 |
|------|------|
| 扮演回复 | 先查目录 → 中间态 → 原文摘录；prompt 要求先根据检索再答 |
| 「调整记忆」 | 展示中间态 + 亲历；档案/目录默认收起；不列聊天全文、不列热词 |
| 对话区 | 仍是日志入口 |
| World Builder | **不改** ingest / retrieve / 抽取引擎 |
| 语音热词 / Agent 短期工作记忆 | **本切片不改** |

## User Control

- 翻日志：就在这次对话里。
- 改/忘掉重要聊天：现有「调整记忆」。
- 改亲历/关系：现有编辑；事件进世界须确认。
- 不提供「删除整段聊天日志」。
- 不提供「编辑热词记忆」「编辑短期记忆」——它们不是角色记忆。

## Recovery

- 取消编辑 / 拒绝提案：认知与世界不变，日志仍在。
- 关掉再开：全文可还原；下一句仍先检索再答。
- 短期窗口被压缩：用目录 + 中间态 + 原文摘录找回，不靠窗口当档案。

## Acceptance Criteria

```text
[ ] 扮演对话全文关掉再开仍在
[ ] 「调整记忆」展示精简重要聊天 + 亲历，不出现聊天复读，不出现热词/短期窗口/滚动摘要
[ ] 窗口满了：旧句退出 prompt 并折进摘要；对话区全文仍在；问摘要之外的旧事能靠检索答上，不把整本日志塞进下一轮
[ ] 用户问确有的事（还记得 / 当时做了）：先查目录再答，能对上中间态或摘录，不编相反细节
[ ] 用户问都没有的事：角色表示记不清，不编造
[ ] 检索不得带入当前锚点之后的扮演线程，也不得带入 World Builder 对话
[ ] 世界事件未确认不进时间线
[ ] 取消编辑不写库
[ ] 不改 Prisma schema；不为短期记忆/热词新建表
[ ] World Builder 行为本切片不变
[ ] Empty / Loading / Success / Error / Retry / Cancel 均有中文
```

未完成：只有日志和碎片要点、没有可读中间态；或把短期窗口/热词画成角色记忆。

## Out of Scope

- Agent 工作记忆 / 工具循环
- 热词重载实现（派生索引，跟语音/Agent 走）
- 把短期窗口升级成可编辑的第四层记忆
- 独立「聊天日志浏览器」或跨线程时间轴 UI
- 删除或编辑 L0 原文
- 群聊、角色复制/导入、World Builder 抽取引擎
- 新向量库

## Implementation Constraints

1. 复用现有三张表：消息 = 日志，原子 = 中间态，核心 = 目录。先让展示和检索按这个读，再收敛抽取（不要每句都进中间态）。
2. 扮演检索：目录 → 中间态 → `sourceMessageId` 原文摘录。范围 = 该角色的 `RoleplayThread` + 手工事实；WB 排除。
3. 原文摘录要截断，条数有上限。
4. 用户文案：对话记录 / 重要聊天 / 先查再答。禁止对扮演用户讲 L0/L1/L2、embedding、热词、工作记忆。
5. 测试：三层分工、记得/不记得、时间边界、展示不含复读、Journey F 日志仍在、与 WB 隔离、短期窗口不出现在「调整记忆」。
