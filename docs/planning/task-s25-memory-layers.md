# Feature

功能名称：按世界时间记得（P0-08a · 角色交谈记忆）

> Status: **Implemented — 2026-09-16（修订）**。扮演按世界时间读角色认知；聊天全文留在 L0 日志，提取要点进 L1/L2 再检索；灌进角色时仍按锚点过滤。
>
> 所属 Journey：**C（第一次与角色生活）**「角色记住重要信息」
>
> 闭环位置：创建世界 → 创建角色（已完成）→ **在世界时间点上，TA 只记得该记得的；交谈偶尔留下记忆/事件（本切片）** → Agent 运行时完善世界（更后面）→ 群聊
>
> 宪法依据：产品宪法 Journey C/E、立宪裁决「聊天与世界」「记忆」；[AI-Agent-Collaboration.md](../domain/AI-Agent-Collaboration.md) §2.3 Roleplay ≠ 流水线角色。世界 = `Project`。

## 产品分界（本修订的核心）

聊天和 Agent **共用一个世界**，**不共用同一套运行时记忆模型**。

```text
                    ┌──────────── Project（世界真源）────────────┐
                    │  Asset / WorldEvent / Relationship / 角色卡 │
                    └──────────┬───────────────────┬─────────────┘
                               │                   │
              角色交谈 Runtime │                   │ World Builder Runtime
              （注重角色记忆）  │                   │ （注重工具，完善世界）
                               ▼                   ▼
                    按世界时间读角色认知        工具调用 + 提案确认写世界
                    交谈中偶尔写入              动态压缩 / 工作记忆 / 权限
```

| | **角色交谈（Chat / 扮演）** | **Agent（World Builder / 副驾驶）** |
|--|------------------------------|-------------------------------------|
| 用户在跟谁说话 | 世界里的角色（林夕） | 帮你完善世界的助手 |
| 成功长什么样 | TA 像活在这个时间点；记得亲历，不知道未来 | 设定被补全、可确认、写进 Studio |
| 记忆是什么 | **角色认知**：此刻 TA 经历过什么、和谁什么关系、性格与档案 | **运行时状态**：本轮任务进度、工具结果、压缩后的对话窗口、创作者偏好 |
| 时间 | **世界时间锚点决定记得什么** | 任务时间：这轮工具做完就清空工作记忆 |
| 写入 | **偶尔**：对白里冒出的事 → 记忆或事件提案；不是每句落库 | **主要靠工具/提案**：创建角色、地点、规则；确认后写世界 |
| 权限 | 禁止静默改世界；改事件/关系/卡必须确认 | 同样确认围栏；工具默认无写世界权，只有「起草提案」 |
| 主流范式 | 时间锚定角色状态 + 认知边界（已有雏形） | ReAct：推理 ↔ 工具；上下文动态压缩；三层是 **Agent 内部**，不对扮演用户讲 |
| 面试稿三层 / 热词重载 | **不作为扮演产品模型** | 落在 Agent 运行时（后面单独切片） |

不引入第二套向量库。不把 L0/L1/L2 画在「调整记忆」上教用户。存储仍是现有表；**差别在读法、写法和提示词组装**。

### 比「两套记忆产品」更好的做法

不要做成「聊天记忆 App」+「Agent 记忆 App」。Zivith 的优势是世界是真源：

1. **读**：扮演只组装「这个角色 + 这个锚点」的认知；Agent 组装「当前任务需要的世界切片 + 工具结果」。
2. **写**：扮演默认只说话；重要内容**偶尔**变成可确认条目。Agent **默认调用工具**去补世界，结果仍是提案。
3. **压缩**：扮演压缩的是这次对白窗口（让聊得下去），不是角色的人生。Agent 压缩的是工具轨迹与任务上下文。
4. **热词/向量重载**：派生索引纪律留给 Agent/语音/检索，不塞进角色「记得什么」的故事里。

今天代码已经部分站在正确一边：`buildCharacterState` 按锚点过滤亲历事件、锚点后事件用于防剧透。走偏的是：扮演每轮还做一次**项目级** `retrieve` 灌进 prompt，原子列表也不按世界时间切；等于把 Agent 检索和角色人生混在同一句里。

## 为什么先做交谈记忆，不先做 Agent 三层

| 项 | 处理 |
|----|------|
| 用户已能创建林夕并开口 | 下一句要像「这个时间点的人」，否则 Journey C 停住 |
| Agent 动态压缩 / 工具循环 / 权限 | World Builder 已有提案确认，不是本切片；抽取引擎、完整 ReAct 留后面 |
| 群聊 | 每个角色先有自己的时间认知，否则只是轮流说话 |
| 复制导入 | 便利项 |

## User Problem

已经能和角色说话，但：

- 换了世界时间，TA 仍可能用到还不该知道的检索片段（项目级 digest）。
- 「调整记忆」和 Agent 的 L1/L2 面板像同一件事，用户分不清「角色记得」和「助手在记任务」。
- 每句用户话都 ingest，不像「偶尔写入」。

## User Goal

1. 选一个时间锚点（或全书读完），角色只按该时刻的亲历、关系、当时的卡说话。
2. 打开「调整记忆」看到的是 **这个角色在这个时间** 记得什么，不是 Agent 工作记忆。
3. 交谈中冒出的重要事：**偶尔**变成可查看的记忆，或待确认的事件；取消则世界不变。
4. 改完记忆或换锚点，下一句按新认知说。

成功时用户知道：我在跟这个时间点的林夕说话；不是在给 Agent 布置完善世界的任务。

## Entry

- Chat 扮演线程顶栏：时间锚点 + 「调整记忆」（已有）。
- Studio 选中角色：「TA 记得什么」（已有）。
- 不新开 Agent 记忆设置页。没有角色时走已完成的「创建角色」。

## Main Flow

```text
已有世界、已有角色、已进入扮演
    ↓
当前时间锚点 T（某事件之后 / 全书读完）
    ↓
组装角色认知：T 及以前的亲历 + 当时关系/卡 + 用户改过的、在 T 仍有效的事实
    ↓
不含：锚点之后的事、其他角色的私密、Agent 任务摘要、项目级无关检索
    ↓
用户说话 → 角色按该认知回复
    ↓
若这轮出现「值得记下」或「世界可能变了」：
    偶尔产出记忆条目（可改/可忘掉）和/或事件提案（须确认）
    不是每轮都写
    ↓
用户改锚点或改记忆 → 下一句重新组装认知
```

## States

### Empty

- 该角色在 T 没有亲历、没有短事实：说明「在这个时间点，TA 还没有可说的经历。可以聊；重要的事出现后再记下或确认进世界。」
- 导入「出场 N 章」仍不当成剧情记忆。

### Loading

- 保存记忆 / 切换锚点：沿用现有中文等待，禁止连点。

### Success

- 回复不引用 T 之后的事件标题/情节（现有防剧透保持）。
- 「调整记忆」与下一句认知一致。
- 偶尔写入的条目能在同一角色下看见；事件须确认才进时间线。

### Error

- 「没能保存记忆 / 没能更新认知。请再试一次。」保留草稿。

### Retry

- 同一条再保存；锚点再切一次。

### Cancel

- 关掉编辑、拒绝提案：不写原子、不写世界。

## Data

| 数据 | 扮演怎么用 | Agent 怎么用（本切片不改） |
|------|-------------|--------------------------------|
| `WorldEvent` | **读**：仅 T 之前且该角色亲历 | 工具起草，确认后写 |
| `Relationship` / 角色卡修订 | **读**：尽量对应该时刻 | 确认后写 |
| `MemoryAtom`（挂该角色） | **读**：在 T 仍有效的提取要点；**写**：从聊天抽取，不是把整句当人生 | 可检索世界设定，不作「林夕的人生」 |
| `MemoryCore` | 档案补充 / 聊天要点目录 | 主题凝练给助手 |
| `CreatorChatMessage`（L0 日志） | 聊天全文，不删 | 助手本轮窗口另算 |
| `ThreadContextState` | 对白窗口压缩，让聊得下去 | 任务上下文压缩 |
| 提案 pending | 交谈里偶发的世界变化 | Agent 的主输出 |

不新建表。不引入 Chroma / Milvus / Redis。

## Cross-module Impact

| 模块 | 变化 |
|------|------|
| 扮演 prompt | 以 `buildCharacterState` 为认知主源；聊天要点 digest 须过锚点过滤 |
| ingest | 扮演恢复抽取：全文在 L0，要点进 L1/L2；不把整句当世界事件 |
| 「调整记忆」文案 | 角色 + 世界时间；说明全文在对话记录、要点用于检索 |
| World Builder | **本切片不改**抽取引擎、不改工具循环 |
| 语音热词 | 不在本切片 |

## User Control

- 换锚点：用户选。
- 改角色记得的事：用户保存。
- 事件/关系/卡进入世界：确认。
- Agent 完善世界：走世界 Tab / 创作聊天，不从扮演顶栏进去。

## Recovery

- 取消编辑 / 拒绝提案：认知与世界不变。
- 关掉再开：对白还在；角色认知仍按锚点组装（Journey F）。

## Acceptance Criteria

```text
[ ] 扮演「调整记忆」只表达角色在当前世界时间记得什么，不出现 Agent 三层/L1/L2
[ ] 有锚点时，prompt 组装不含锚点之后的事件；项目级检索不得把未来剧情灌进角色
[ ] 用户改一条该角色事实或换锚点后，下一句按新认知
[ ] 交谈全文留在对话记录（L0）；提取要点进检索（L1/L2），灌进角色时不得突破锚点
[ ] 未确认提案不写入 WorldEvent / 世界层
[ ] 取消编辑不写库
[ ] 不改 Prisma schema；不新建记忆表 / World 表
[ ] World Builder 行为本切片不变
[ ] Empty / Loading / Success / Error / Retry / Cancel 均有中文
```

未完成：角色仍按项目大杂烩检索说话；或把「待确认提案」画成角色的人生。

## Out of Scope

- Agent 运行时切片（动态压缩、工具循环、权限矩阵、推理-行动融合）——**另开任务**，面试三层放那里
- World Builder 抽取引擎升级
- 群聊、角色复制/导入
- 把 L0 对话改成关会话即删
- 新向量库产品
- 热词重载（属派生索引，跟 Agent/语音走）

## Implementation Constraints

1. 复用 `buildCharacterState`、时间锚点、防剧透、`CharacterArchive`。先改**读路径**（认知组装），再收敛扮演 ingest。
2. `MemoryAtom.validTo` 已有；扮演读取应按锚点过滤（设计文档已写，代码尚未按 T 切原子）。必须改 schema 则停下来报告。
3. 用户文案：角色 / 世界时间 / 记得什么。禁止对扮演用户讲工作记忆、工具、embedding。
4. 测试：锚点前记得、锚点后不知情、改事实下一句用上、取消不写、全书读完、与 World Builder 线程互不污染认知。

## 实现顺序（确认后执行）

1. 扮演读路径：认知 = 锚点过滤后的亲历 / 关系 / 卡 / 该角色有效原子；去掉越界 digest。
2. 「调整记忆」文案改为角色+时间；与组装结果一致。
3. 写入保持偶尔 + 确认围栏（不扩大自动 ingest）。
4. 测试：时间边界、改记忆、取消、与世界构建线程隔离。
