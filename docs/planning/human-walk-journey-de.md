```powershell
docker compose up -d --wait postgres redis
$env:NODE_OPTIONS='--max-old-space-size=4096'
pnpm --config.engine-strict=false --filter @zivith/api --filter @zivith/web --parallel run dev
```

也可以双击仓库根目录 `Zivith.vbs`（仍要 Docker + Node，不是免安装）。

若网页打不开：先看 Docker 是否 Healthy，再看两个开发服务是否还在跑。上次 Next.js 曾把内存吃满退出，再启动时请带上上面的 `NODE_OPTIONS`。

## 1. Journey E：单角色（先做这条）

目标：一个人说话，世界真的往前走。
没看到，有可能聊少了
### 1.1 进入扮演

1. 打开 http://127.0.0.1:3100
2. 左侧点世界 **龙族**
3. 侧栏顶上 Tab 切到 **「角色」**（不要停在「世界」——那是世界构建者，会反复检查设定冲突，不是扮演闭环）
4. 在「龙族」这一行点 **对话加号**（「开始扮演」），或点「选择或创建角色开始扮演」
5. 选 **路明非**
6. 时间保持 **全书读完**
7. 「你是谁」保持 **读者**
8. 点 **开始扮演**

标题应是：`与「路明非」对话`。顶栏有 **Studio**。
ok
### 1.2 先闲聊一轮（应无世界提案）

发送类似：

```text
师兄今天食堂吃什么？
```
回答
食堂？师兄在这船上，食堂的菜谱我熟——鸡胸肉、西兰花，顶多再来个全麦面包，楚子航吃饭跟执行任务似的。

**通过：** 有角色回复；这条回复下面**没有**「确认 / 拒绝」提案卡；也不出现「已记录」「已写入世界」之类空承诺。  
底部若闪过「正在整理这一轮对世界的影响…」而后**没有**提案，也算正常（闲聊本来就不该改世界）。

**失败：** 闲聊也出一张假事件；或提示已经写入世界，但你没点确认。

### 1.3 说一件会发生在世界里的事

发送类似（请整句发出，不要只打招呼）：

```text
路明非，今晚你在卡塞尔学院天台把「你见过龙王」这件事当面告诉了诺诺。这件事已经发生了。
```

等他对白说完。
回答
天台？我？当面跟师姐说你见过龙王……我要是真有这么有种，还用得着在港口那半个月自己跟自己打架。这事儿我记不清，你别拿它堵我，我这人胆子小。
**通过：**

- 对白像这个人在说话（不像旁白上课）
- 对白结束后，同一条回复下方出现提案卡
- 卡上是中文，能看懂是事件 / 关系之类，人名是「路明非 / 诺诺」不是一串 id
- 提示类似：`每步确认：确认后才写入世界，拒绝则世界不变`
- 按钮：**确认**、**拒绝**、**查看**

**失败：**

- 只有对白，永远没有提案（说了明确已发生的事仍没有，记下来：原话 + 是否出现「正在整理…」）
- 提案内容与刚才说的无关（例如编了一场没发生的主线）
- 还没点确认，Studio 里已经有这件事

生成太久：点发送键变成的 **停止**（取消这一句思考）。对白按现有规则处理；未发出的提案不应落库。

### 1.4 先拒绝一次（证明世界不变）

1. 点 **拒绝**
2. 徽章应为 **「已拒绝 · 世界未改变」**
3. 对白还在
4. 点顶栏 **Studio** → 中间时间线、左侧树里的事件，**不应出现**刚才那张提案里的新事件

**失败：** 拒绝后时间线仍多了一条；或对白被删掉。

### 1.5 再说一遍并确认

再发一次 1.3 那句（或稍改时间地点以免模型以为重复）。等提案出现后：

1. 点 **确认**（多条时是「确认全部」）
2. 应变为 **「已写入」**
3. 若确认失败：红字「没能写入世界」，对白仍在；再点确认，不要重开一场聊天
4. 成功后点卡片上的 **「在 Studio 查看 →」**，或顶栏 Studio

**Studio 里应能看到：**

- 时间线上多了刚才确认的事件（标题能对上）
- 若提案含关系：角色之间能看到这条关系
- 点路明非：右侧 Inspector / 档案不是空白旧状态

**失败：** 卡上已写入，时间线没有；必须手动刷新才出现也算本项弱失败（记下）。
ok
### 1.6 再进对话，角色要用上这件事

不要新开线程。回到刚才那条「与路明非对话」，发送：

```text
你还记得今晚在天台对诺诺说的事吗？你当时说了什么？
```

**通过：** 他承认发生过，能对上你确认的那件事（不必逐字，不能装没发生）。  
点 **调整记忆**：这个时间点的经历里应能对上（至少时间线那条事件绑在他身上）。

**失败：** 完全不认；或只在对白里说「我记住了」但记忆/时间线没有。
ok
### 1.7 离开再进（提案未确认时应还在）

可选：再引出一张新提案，**不要点确认**，关掉标签或回项目列表，再打开同一条对话。

**通过：** 未确认提案还在，没有自动写入、没有自动消失。  
然后再确认或拒绝，世界只在确认后变。

## 2. Journey D：群聊（E 通过后再做）

目标：两个人互相说、你能插话，**并且**群戏也能把事件写进世界。

请 **新建一场群聊**，不要用旧的「路明非 / 诺诺」长线程（里面已经有很多空拍，提案和记忆会搅在一起）。

### 2.1 开场

1. 侧栏 Tab **角色** → 龙族行点 **多人图标**（「开始群聊」），或点「开始群聊」文字
2. 勾选 **路明非**、**诺诺**（只要 2 人；3 人也可以，第一遍建议 2 人）
3. 时间：**全书读完**
4. 「你扮演」：**读者（默认）**
5. 点 **开始群聊**

标题应是：`群聊 · 路明非、诺诺`。
怎么创建不了
### 2.2 互聊与插话（世界变化之前）

1. 先发一句把他们放到同一现场，例如：

```text
你们现在都在卡塞尔学院天台。先别走，互相说两句。
```

2. 他们会按拍接话（上一句上屏后再等约 3.5 秒）。  
3. 点 **暂停交流**：他们应停下等你（正在生成的那一句不会因为这个按钮被掐掉）。  
4. 点 **继续交流** 或再打字发送 = 插话。  
5. **停止**（发送键）才是取消正在思考的那一句。  
6. 点 **让他们各说一句**：两人各来一拍。  
7. **让他们一直说**：他们自己找话题；有待确认提案时应停下。点 **停下来** 或打字都会停。  
8. 右侧竖着的小横条：悬停能看到是谁说的；点一条会弹出回退确认。先点 **取消**，对话不应变。

**通过：** 能看清谁在说话；能停、能插话；回退取消不改历史。  
**角色感（已做、可顺手记）：** 两人口吻不像同一套旁白；括号动作不要每句都是船舷/插兜。不作为本轮「闭环失败」的唯一理由。

「你扮演」可换成书中角色；换成后才有 **AI 接管**。本轮闭环不强制测接管；若顺手测：接管句应是该角色的用户气泡，打字后应回到「我来演」。

### 2.3 群戏里发生一件事 → 提案 → 确认

暂停交流后发送一件**已经发生**的事，例如：

```text
刚才天台上，诺诺当着陆明非的面把学生会的紧急召集令撕了。这件事已经发生了。
```

等在场的人说完（可能每人一句）。

**通过：** 某一条（通常是助理回复）下面出现提案卡；人名可读；你点 **确认** 后 Studio 时间线出现对应事件。  
点 **让他们一直说** 时若已有待确认提案，应停住并提示「有待确认的世界变化」。

**失败：** 群聊永远不出提案（即使你说了已发生的事）；或未确认就写进时间线；或确认后 Studio 没有。

### 2.4 再进群聊

同一条群聊继续问：

```text
诺诺，你还认不认刚才撕召集令这件事？路明非，你当时在场看到了什么？
```

**通过：** 在场的人按各自立场认这件已确认的事，不能集体装没发生。  
两人知道的应能不同（分人认知），不要两人背同一段说明书。

### 2.5 回退（可选，记现象即可）

点某条角色侧边横条 → **确认回退**。

**预期：** 该句还在，后面的对话视为没发生；本场已确认、排在回退点之后的写入会被拿掉。  
**不要**指望 L0 记忆原文从磁盘物理删除。

若回退把你刚确认的事件也拿掉了：记下是哪一句、时间线上那条事件是否还在。这是有效 bug，不是操作错误。
