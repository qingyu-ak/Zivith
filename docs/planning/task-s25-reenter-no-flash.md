# Feature

功能名称：再进扮演不要先闪成「新世界对话」

> Status: **Implemented — 2026-09-24**。再进扮演 URL 加载中不再显示「新世界对话」/「发给世界构建者」。确认本任务单后已落地。
>
> 所属 Journey：**D（再进对话）**，并补 **F（回来继续）** 里「进入项目 → 继续聊天」
>
> 宪法依据：[Product Constitution](../product/Product-Constitution.md) Journey D/F、§5 六态、§25
>
> **确认前不写代码。** 不改数据模型，不新建 `World` 表。

## User Problem

用户遇到的问题：

已经有一场扮演。从 Studio 点回来、刷新、或粘贴 `/creator-chats/:id`，先看到：

- 标题「新世界对话」
- 输入框「发给世界构建者…」
- 侧栏「世界 0 / 角色 0」和「点新建世界从零开始」

用户会以为这场对话丢了、世界没了。一两秒后才变回扮演。内容其实还在，但再进这一步不像「回来继续」。

## User Goal

用户希望完成：

打开一条**已经存在**的对话时，加载过程不像在新建世界。加载完仍是原来的扮演或世界构建。打不开时才说「对话不存在」。

成功时用户知道：我在打开刚才那条对话，不是从零开始。

## Entry

入口：

- 侧栏点已有扮演 / 群聊
- Studio 点 Chat / 某条对话
- 地址栏打开 `/creator-chats/:threadId`
- 从 Studio 世界页再进同一 URL（本次走查的路径）

无 `threadId` 的 `/creator-chats` 仍是「新世界对话」，不改。

## Main Flow

正常流程：

```text
打开已有 /creator-chats/:threadId
        ↓
加载中：标题 / 输入 / 侧栏不装成新建世界
        ↓
拉到线程：按 kind 显示扮演或世界构建
        ↓
用户继续说话
```

## States

### Empty

- 没有 `threadId`：现在的新世界空态，保留。
- 有 `threadId` 且正在加载：**不是** Empty，是 Loading。禁止用「新世界对话」顶替。

### Loading

- 对话区已有「正在加载对话…」（保留）。
- 标题：侧栏列表若已有这条，用它的标题；否则「正在打开对话…」。
- 输入框：禁用，占位「正在打开对话…」，不要「发给世界构建者…」。
- 侧栏：工作区列表还没回来时「正在加载工作区…」，不要「点新建世界从零开始」，不要「世界 0 / 角色 0」装成空账户。

### Success

- `kind=roleplay`：标题、扮演条、对「某角色」说…，消息还在。
- 世界构建线程：才是发给世界构建者。
- 待确认提案还在（本切片不改提案逻辑）。

### Error

- 已有「对话加载失败 / 对话不存在 / 重试」。保持。
- 失败页不要再套一层「新世界对话」当主标题也可以，但失败文案必须看得见。

### Retry

- 现有「重试」再拉同一 `threadId`。加载中重新走 Loading，不闪新建世界。

### Cancel

- 离开这条 URL / 另开一条对话：扔掉进行中的 GET，回来的旧响应不得写到新页面上。

## Data

涉及数据：

- 只读：`GET /world/creator-chats/:id`、列表、扮演线程列表。
- 不产生新世界实体。谁消费：Chat 面板标题、输入框、侧栏。
- 改完之后：再进同一 URL、Studio→Chat、刷新、删掉的 URL（仍 404）应一致。

## Cross-module Impact

影响哪些模块：

- Chat：`chat-panel.tsx`、`chat-sidebar.tsx`，标题/占位判定收到 `chat-history` 一类纯函数，便于单测。
- Studio：不改。
- API / 数据模型：不改。

## User Control

哪些操作需要用户确认：无。这是打开已有对话的展示，不是写世界。

## Recovery

如何撤销 / 恢复：关掉再打开同一 URL；失败点重试。没有新写入可撤销。

## Acceptance Criteria

完成标准：

1. 从 Studio 再进走查雾城信「与林晚对话」：加载过程中看不到「新世界对话」当标题，看不到「发给世界构建者」当输入占位，侧栏不装成空账户。
2. 加载完成后仍是扮演（标题、对林晚说、消息还在）。
3. `/creator-chats` 无 id：仍是新世界对话。
4. 已删对话 URL：仍「对话不存在」，世界还在。
5. 快速连点两条对话：后一条的内容不被前一条的慢请求覆盖。
6. 取消加载（离开页面）不留下半截状态。
7. 单测：有 threadId + loading 不得得到「新世界对话」标题；列表已有该线程时用列表标题。

## Out of Scope

本次明确不做：

- 免 Docker 安装包
- 角色导入、World Builder 抽取
- 改提案 / 删对话逻辑
- 用 sessionStorage 记住上一次扮演条（本刀只修加载态，不做跨页缓存）
- 日历时间、账号、下载站

## Implementation Constraints

实现约束：

1. 用户说的世界仍是 `Project`。
2. 不改表、不改路由形状。
3. 从 `develop` 开 `fix/reenter-no-flash`，做完再合并；不直接在 `develop` 上改。
4. `load()` 必须带当前 `threadId` 的取消 / 忽略过期响应。
5. 侧栏「空」和「还在加载」要分开。
6. 不把扮演错显示成世界构建：`kind` 已知时听 `kind`，未知时宁可 Loading 也不要假装世界构建者。
