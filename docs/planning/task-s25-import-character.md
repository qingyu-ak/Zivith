# Feature

功能名称：从其他世界导入角色卡

> Status: **Implemented** — 2026-09-24。`feat/import-character`。Studio 从其他世界导入角色卡；同世界复制带上外貌/个性/别名/常服。不搬记忆和事件。
>
> 所属 Journey：**C（与角色生活）** 的入口补全，服务 **A（第一次使用）** 里「已有世界再来一个能开口的人」
>
> 宪法依据：[Product Constitution](../product/Product-Constitution.md) Journey A/C、模块 Character「创建角色 / 角色可持续使用」、§5 六态、§25
>
> **确认前不写代码。** 不改数据模型，不新建 `World` 表。角色仍是 `Asset(type=character)`。

## User Problem

用户遇到的问题：

已经在一个世界里养好了角色（例如走查雾城信的林晚）。到另一个世界还要再填一遍名字和简介。同世界可以点「复制」，换世界没有入口。

核对现状（2026-09-24，未改代码）：

- Studio 角色行有「复制」：`copyWorldCharacter`，只拷贝名字（加「副本」）、简介、个性。不拷外貌、别名、服装。
- 没有「从其他世界导入」。
- TXT / 小说导入是另一条路，不替代「把已有角色卡拿过来」。
- 记忆、事件、关系属于源世界，导入时不应跟着搬。

## User Goal

用户希望完成：

在当前世界里，从本机另一个世界选一个可扮演角色，确认后这里多一张能开口的卡。源世界不变。马上可以点对话。

成功时用户知道：这是这个世界里的人，不是把那边的记忆和事件偷过来。

## Entry

入口（当前世界）：

1. Studio 资源树「角色」：在「+ 角色」旁加「从其他世界导入」。
2. 不新开大壳。弹层选世界 → 选角色 → 确认。

Chat 角色 Tab 本刀不做第二套入口（避免两处 UI 分叉）。需要对话时用导入后卡片上已有的「对话」。

没有当前世界：先走新建/打开世界，本功能不创建世界。

## Main Flow

正常流程：

```text
打开当前世界 Studio
        ↓
从其他世界导入
        ↓
选一个有角色的其他世界
        ↓
选一个可扮演角色（不是「我」）
        ↓
确认导入
        ↓
本世界新建 Asset(character)
        ↓
树里出现；可改卡、可对话
```

同世界「复制」仍可用。本刀把复制与导入收成同一套「拷卡片字段」，复制不再只带名字和简介。

## States

### Empty

- 本机没有其他带可扮演角色的世界：说明「没有可导入的角色。先在别的世界创建，或在这里新建。」+ 关闭。
- 选了世界但该世界 0 个可扮演角色：该列为空说明，不提交。

### Loading

- 拉世界列表 / 拉该世界角色时：加载中，不能连点确认。
- 导入中：确认按钮忙碌，不能重复提交。

### Success

- 本世界多一张卡：名字、简介、个性、外貌文字、别名、默认服装与源卡一致。
- 本世界已有同名：名字用「原名 副本」（与现有复制同一套 `nextUntitledName`）。
- 源世界角色、事件、记忆、对话一个不改。
- 新卡没有源世界的记忆原子、世界事件、关系、扮演线程。

### Error

- 源角色已删 / 源世界打不开：中文错误，可关可重试。
- 写入失败：世界未增加半张卡（失败则不留下未命名角色）。

### Retry

- 失败后可再确认。已成功的不再插第二张，除非用户再走一遍入口。

### Cancel

- 关弹层 / 取消：不写库。
- 选到一半取消：不写。

## Data

涉及数据：

- 读：本机 `Project` 列表；源世界 `Asset(type=character)` 卡片字段。
- 写：当前 `Project` 一条新 `Asset`。`POST /projects/:id/assets`（现有）。
- 拷贝字段：`name`（冲突则副本）、`description`、`personality`、`appearance`、`aliases`、`default_outfit`、`state=active`。不拷 `user_self` 标签、不拷 `import_id`、不拷参考图/封面（避免源资源深链）、不拷 `base_character_id`。
- 谁消费：Studio 树、Chat 角色、扮演启动。
- 改了之后：只当前世界角色列表变；源世界 Studio / 对话不变。

## Cross-module Impact

影响哪些模块：

- Web：`copyWorldCharacter` 补全字段；新增 `importWorldCharacter`（源项目 + 源角色 id → 当前项目）。Studio 树一个导入弹层。
- API：尽量不新路由。列表用现有 `/projects` 与 `/world/projects/:id/resources`。若跨项目读角色在现有接口不够，再补只读，不改表。
- Chat / 记忆 / 事件 / 关系：不改。
- 数据模型：不改。

## User Control

哪些操作需要用户确认：导入前必须选世界、选人、点确认。高风险（覆盖源世界）不会发生。

## Recovery

如何撤销 / 恢复：

- 导入错了：用现有 Studio 删除角色（若还没有删除角色，本刀不新做删除；可改名或不用这张卡）。
- 源世界：无变化，无需恢复。

## Acceptance Criteria

完成标准：

1. 在「开折」（或任一非走查雾城信世界）Studio，从走查雾城信导入林晚：开折出现林晚（或「林晚 副本」），简介/个性还在。
2. 走查雾城信的林晚、交信事件、记忆、对话一条不增不减。
3. 导入后可点对话，开的是**开折**的新扮演，不是走查雾城信那条线程。
4. 取消弹层：开折角色数不变。
5. 没有其他可导入角色时：空说明，不空白死页。
6. 同世界「复制」林晚：副本带上个性/外貌文字，不只名字。
7. 单测：冲突改名；不把 `user_self` 当可导入；取消路径不调创建。

## Out of Scope

本次明确不做：

- 导入记忆、事件、关系、对话。
- 从文件 / JSON / 外站导入。
- 一次多选。
- Chat 侧栏第二套导入入口。
- 角色删除（若现有没有，另开一刀）。
- World Builder 抽取引擎、安装包、日历。

## Implementation Constraints

实现约束：

- 从 `develop` 开 `feat/import-character`。
- 不改 Prisma，不新建 `World` 表。
- 世界 = `Project`。导入 = 当前 Project 新建 Asset。
- 安装包仍不插队。
