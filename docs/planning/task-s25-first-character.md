# Feature

功能名称：第一个可对话角色（P0-04a）

> Status: **Implemented — 2026-09-16**。确认后已落地。
>
> 所属 Journey：**A（第一次使用）** 的后半段「创建角色 → 开始聊天」，并打开 **C（与角色生活）** 的入口
>
> 闭环位置：创建世界（已完成）→ **创建 / 导入角色（本切片）** → 进入世界 / 单角色对话（已有扮演）
>
> 宪法依据：产品宪法 Journey A/C、§23「不知道怎么创建角色」、模块表 Character「创建角色 / 角色可持续使用」；世界 = `Project`，角色 = `Asset(type=character)`

从零创建的世界会进 World Builder；Chat「角色」空态只说去 Studio 点「+ 新建」；Studio「+ 角色」会直接落下「未命名角色」。用户无法独立走完「世界 → 角色 → 对话」。

## User Problem

已经有一个世界，但不知道怎样得到一个能说话的角色。

- 从零：World Builder 在问世界观，Chat 角色 Tab 是空的。
- Studio 一点「+ 角色」得到「未命名角色」，不像一个可以一起生活的人。
- TXT 导入的世界已有角色，这条路相对通；缺口主要在从零。

## User Goal

1. 在已有世界里，用真实姓名创建一个角色（简介可选）。
2. 马上能开始与这个角色的扮演对话（现有单角色扮演）。
3. 取消则不留下「未命名角色」。
4. 世界里已有角色时：仍从 Chat「角色」选人开始扮演（现有能力，只补空态）。

成功时用户知道：这个角色属于这个世界、可以改卡、可以对话。

## Entry

不新开大壳页面。三条现有入口收口到同一套「创建角色」：

1. Chat 侧栏「角色」Tab：该世界还没有可扮演角色时。
2. Chat「开始扮演」弹层：该世界没有角色时（今天只有一句去 Studio）。
3. Studio 资源树「+ 角色」：先问名字，不直接建未命名。

World Builder 对话里说「主角叫××」仍走现有提案，本切片不改抽取引擎。

空世界、没有 `Project`：先走「新建世界」，本功能不创建世界。

## Main Flow

```text
已有世界，还没有可扮演角色
    ↓
填写角色名（必填）+ 一句话简介（可选）
    ↓
确认创建
    ↓
写入 Asset(character)，state=active
    ↓
询问：开始与 TA 对话？
    ↓
是 → 现有 createRoleplayThread → /creator-chats/:threadId
    否 → 留在当前面，角色已出现在列表 / 资源树
```

已有角色：选角色 → 现有扮演启动（锚点 / 你扮演谁），本切片不重做。

## States

### Empty

- 该世界 0 个非 `user_self` 角色：中文说明「先创建一个角色，才能进入世界和他说话。」+ 表单。
- 名称为空：不能提交。

### Loading

- 「正在创建…」，禁止连点。
- 创建成功后打开扮演：「正在进入对话…」

### Success

- 角色出现在 Chat 角色列表与 Studio 资源树。
- 若选择开始对话：进入该角色扮演线程。
- 名称就是用户填的，不是「未命名角色」。

### Error

- 「没能创建角色。请再试一次。」保留已填名称。
- 打开扮演失败：角色已在，提示「角色已创建，但没能打开对话。请从角色列表再试。」

### Retry

- 同一表单再提交。
- 扮演失败：列表里点该角色再进入。

### Cancel

- 关掉表单 / 返回：不创建 Asset。
- 创建成功后不立刻对话：角色保留（这是成功，不是取消）。

## Data

| 数据 | 谁写 | 谁读 |
|------|------|------|
| `Asset` `type=character` | 用户确认创建 | Chat 角色列表、Studio、扮演 `characterAssetId` |
| `RoleplayThread` | 用户选择「开始对话」后，现有 API | Chat |
| `CreatorChatThread`（World Builder） | 不在本切片创建角色时改 | 从零路径仍在 |

不新建表，不新建 `World` / `Character` 顶层实体。不在确认前写角色。

简介写入现有 `description`（及可选 `personality`，与「你扮演谁」自建卡一致）。不做完整角色卡字段扩张。

## Cross-module Impact

| 模块 | 变化 |
|------|------|
| Chat 角色 Tab / 开始扮演空态 | 可创建角色，不再只指 Studio |
| Studio「+ 角色」 | 先填名称；取消不建 |
| 帮助快速上手 | 第二步改为「创建角色并开始对话」 |
| World Builder `create_character` 提案 | 不改引擎 |
| 扮演 / 世界变化提案 | 不改 |
| TXT 导入角色 | 不改 |

## User Control

- 创建角色必须点确认（表单提交）。
- 开始扮演必须再点一次（或明确的「创建并开始对话」主按钮；次按钮「只创建」）。
- 高风险删除角色本切片不做入口扩张。

## Recovery

- 取消表单：无 Asset。
- 创建失败：无半成品，或仅有用户可见的失败提示且可重试。
- 创建成功、扮演失败：角色留下，可再进。
- 用户可在 Studio 改名 / 改简介（现有 Inspector）。

## Acceptance Criteria

```text
[ ] 从零新建的世界，Chat「角色」空态能填名称创建角色，不必先懂 Studio
[ ] 名称必填；取消不产生「未命名角色」
[ ] 创建后可选立即扮演，进入现有单角色线程
[ ] Studio「+ 角色」同样要名称，不再一键「未命名角色」
[ ] 已有角色的世界（含 TXT 导入）仍能从角色列表开始扮演
[ ] 创建失败可重试；扮演失败角色仍在
[ ] 不改 Prisma schema；不新建 Character 表
[ ] Empty / Loading / Success / Error / Retry / Cancel 均有中文
```

未完成：只会在 World Builder 里口头说「记下了」却没有角色卡；或角色卡无法打开扮演。

## Out of Scope

- 多角色群聊（P0-07）
- 角色复制、从另一世界导入、外观三视图
- 记忆编辑器、时间编辑
- TXT LLM 精抽
- `.zivith` zip
- 密钥服务端持久化
- 改扮演世界变化起草
- 自动把「未命名角色」历史数据全部改名（可在实现时忽略它们，不迁移）

## Implementation Constraints

1. 复用 `POST /projects/:id/assets`、`createRoleplayThread`、现有角色列表。
2. 用户文案称「角色 / 世界」，存储仍是 `Asset` / `Project`。
3. 不改 Prisma schema。必须改字段则停下来报告。
4. `user_self`（用户自己的说话人卡）不是本切片的「世界角色」；空态统计排除它们。
5. 测试：空世界创建、空名拒绝、取消、创建后扮演、创建后不扮演、Studio 加号要名称、已有角色回归、失败重试。
