# Feature

功能名称：扮演中途 AI 接管（Journey D）

> Status: **Implemented — 2026-09-21**。产品所有者确认：用户正在用某个角色聊天时，可以把这个角色交给 AI，由它替用户这个角色接着说。
>
> 所属 Journey：**D（多角色互动）**；1:1 扮演同样可用。
>
> 宪法依据：产品宪法 Journey D、§8–10。世界 = `Project`。不改数据模型。

## User Problem

已经能用顶栏「你扮演」换成书中角色自己打字，但演到一半只能继续手打或退出扮演。没有办法把这个角色交给 AI 接着说。

## User Goal

用户希望：我还是这个角色；点一下，AI 替我说；我想接回来时打字或点「我来演」。

## Entry

扮演对话（群聊或 1:1）。顶栏「你扮演」已选中一个书中角色（不是「读者」）。输入区旁出现「AI 接管」。

## Main Flow

1. 用户正以角色 X 说话。
2. 点「AI 接管」。X 的下一句由 AI 生成，显示为用户这一侧（和自己打的一样）。
3. 对方按原节拍接话（群聊 3.5 秒拍间）。接管开着时，X 会按轮次继续由 AI 开口，上限与「让他们一直说」相同（40）。
4. 用户打字发送、点「我来演」、暂停交流或停下来 → 接管结束，X 重新由用户打字。

## States

### Empty

还没说话也可以接管：AI 以 X 先开口。读者身份不显示该按钮。

### Loading

生成中：按钮不可点；可点发送键上的停止取消这一句思考。

### Success

右侧出现 X 的一句；随后对方接话。横幅说明正在替你演 X。

### Error

失败横幅，对白未写入。可再点「AI 接管」。

### Retry

同一套错误横幅。不另做接管专用重试。

### Cancel

我来演 / 打字 / 暂停交流 / 停下来 / 停止思考。进行中的一句可停；已出现的对白留下，可用刻度回退。

## Data

- 不新建表。生成句写入现有 `CreatorChatMessage`：`role=user`，`speakerAssetId=user_character_asset_id`。
- 谁消费：对话 UI、刻度、记忆 ingest（与用户手打同一条路）、对方角色的下一拍 cue。
- 改了之后：Chat 立刻显示；关掉再开仍在；回退引擎可撤。不静默写世界；对方若提出世界变化仍要确认。

## Cross-module Impact

扮演 API、Chat 面板、群聊节拍。Studio Agent 不接管。不改角色卡、不改记忆层结构。

## User Control

接管本身不写世界。世界变化仍走提案确认。高风险操作不因接管而绕过。

## Recovery

刻度回退 / 撤回该句。我来演只停止之后的代打，不撤销已经说的。

## Acceptance Criteria

- [x] 读者身份没有「AI 接管」
- [x] 扮演角色 X 时点「AI 接管」，出现 X 的一句（用户气泡），对方会接
- [x] 接管中可点「我来演」或打字接回；之后 AI 不再替 X 说
- [x] 暂停交流 / 停下来 / 停止思考会打断等待或生成
- [x] 失败、空场、取消、再进入线程后接管不会自己开着
- [x] 不新建领域表；不改「你是谁不能和正在开口的角色重复」

## Out of Scope

角色感 / 心情旋钮、读者代打、把群聊里已在开口的 AI 角色改成用户演、4+ 人、会话分支。

## Implementation Constraints

- 不改数据模型。
- 复用现有扮演生成与拍间留白。
- 代打句是用户句，不是再加一个 AI 说话人进 roster。
