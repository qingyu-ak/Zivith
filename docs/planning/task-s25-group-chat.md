# Feature

功能名称：同一世界里的多角色群聊（Journey D · v1）

> Status: **Implemented — 2026-09-16**。群聊 2–3 人、每人单独认知、暂停思考、插话、用户句刻度回退/撤回（含本场已确认写入软删）。接话节奏：用户说完后在场的人按拍接一句；点名后另一人可自然回一句。「暂停交流」只停互聊不取消思考；顶栏「你扮演」可换成书中角色。「让他们一直说」空拍自己从关系/亲历找话题。World Builder 抽取引擎 / 复制导入 / Agent 三层与热词重载仍不做。
>
> **停车：** 实测积压（互聊太快、角色句回退与侧面竖条、扮演中途 AI 接管、角色感）见 [next-session-2026-09-16.md](next-session-2026-09-16.md)。先分析再改，确认前不写代码。
>
> 所属 Journey：**D（多角色互动）**
>
> 闭环位置：单角色生活 + 按时间记得 + 三层交谈 + 世界变化提案（C / E 已落地）→ **两人以上能在同一场对话里互相说、用户能插话（本切片）** → 复制导入 / WB 抽取引擎 / Agent 三层与热词重载（另开）
>
> 宪法依据：产品宪法 Journey D、§8–10、立宪裁决「聊天与世界」「记忆」；世界 = `Project`。任务书 P0-07 只作对照，不按总任务书插队。

## 为什么选这一项

四项里只做一项。按 Journey 缺口，不是按功能列表。

| 候选项 | 对应 Journey | 本切片 |
|--------|--------------|--------|
| **群聊** | **D 整段还没有** | **做** |
| World Builder 抽取引擎 | B 已能提案写世界；抽取目标与扮演不同（完善设定 ≠ 偶尔记住聊天） | 不做。聊天和 Agent 本来就不该同一套抽取 |
| 角色复制 / 导入 | 便利。创建角色、TXT 导入已有；不阻塞「再找一个能开口的人」 | 不做 |
| Agent 三层 + 热词重载 | 不是用户 Journey。热词是语音派生索引；Agent 工作记忆不对扮演用户讲 | 不做 |

前置已经齐：世界里能建多个角色；每人有时间认知和三层交谈；扮演改世界仍走提案确认。没有群聊，用户停在「我和林夕」，走不完「选择多个角色 → 开始群聊」。

「你是谁」已经能让用户用另一张卡对**一个** AI 角色说话。那不是群聊。本切片是 **两个以上 AI 角色在同一场对话里开口**。

## User Problem

已经能分别和林夕聊、和陈默聊，但：

- 不能把他们放进同一场对话
- 他们不会对着对方说话
- 用户插不进「两个人正在吵」的现场
- 因此 Journey D 的「产生事件 → 世界变化」没有群戏可确认

## User Goal

用户希望完成：

1. 在已有世界里选出 **2 或 3 个** 可扮演角色，开始一场群聊（同一时间锚点）。
2. 看清 **谁在说话**；每个人只用自己的亲历、关系、重要聊天来答。
3. 用户可暂停、插话、撤回；每一次发出的话是一个刻度，点开可回退到那一句。也可以指定下一位开口，或让在场的人各说一句。
4. 若这场对话让世界可能变化：沿用现有提案卡，确认后进 Studio；拒绝则世界不变。

成功时用户知道：这是一场有几个人在场的交谈，不是把两个单聊叠在一个气泡里。

## Entry

不新开路由。仍是 `/creator-chats/:threadId`，侧栏「角色」Tab。

入口：

1. 该世界可扮演角色 **≥ 2**：侧栏该世界旁增加「开始群聊」（与现有「开始扮演」并列）。
2. 打开后：多选角色（2–3 人）→ 时间锚点（复用现有）→ 「你是谁」（读者，或**不在** AI 发言名单里的一张卡）。
3. Studio 角色卡不作为群聊入口（避免从一张卡误开群）。单角色「与此角色对话」保持现状。

空世界、没有角色、只有 1 个可扮演角色：不能从本功能开始。文案：「再创建一个角色，才能把他们放进同一场对话。」并指向现有创建角色。

## Main Flow

```text
世界里已有 ≥ 2 个可扮演角色
    ↓
点「开始群聊」→ 选出 2 或 3 人 + 锚点 + 你是谁
    ↓
进入同一条扮演线程（群聊）
    ↓
用户说话，或点「让他们各说一句」
    ↓
系统为 **一名** 角色组装认知（只该人的卡 / 亲历 / 关系 / 检索）并回复
    ↓
气泡上是角色名；日志留下全文
    ↓
用户可：暂停 / 插话 / 指定下一位 / 让其余人各说一句
    ↓
顶栏刻度 = 每一次「你发出去的话」；点某刻度可预览该句并回退
    ↓
若本轮使世界可能变化 → 现有提案卡（每步确认）
    ↓
确认 → 时间线 / 关系可见；再聊用更新后的世界
```

发言规则（v1 可控制，不自动连聊）：

1. 用户刚说完：优先 @ 到的人；否则点名；否则与上一句关系最直接的人；再否则名单顺序第一人。**一次只生成一句。**
2. 「让 XX 说」：只生成该人一句。
3. 「让他们各说一句」：在场 AI **每人最多一句**，按名单顺序；用户随时 Stop。
4. 同一人不得在无用户插话、无「再让他说」时连说两句。
5. 暂停某人 = 本场对话不再自动点他；仍可用「让 XX 说」点名。不做跨会话的永久禁言设置页。

## 对话控制：暂停 / 插话 / 撤回 / 刻度回退

对照 Cursor：刻度落在**用户发送**，不是每一句 AI 对白。点某个刻度 → 弹出当时那句用户话 → 「回退到这里」。

四个动作不是同一个按钮：

| 动作 | 何时 | 做什么 |
|------|------|--------|
| **暂停** | 正在思考 / 正在出字 | **取消这一轮思考**。半句不落成完整对白、不提案。大模型不能从同一个 token 接着想；「继续」= 再开一轮。 |
| **插话** | 正在思考或他们还要接着说 | 先暂停这一轮，再把你的新句发出去。 |
| **撤回 / 回退** | 点某条用户消息或刻度 | 同一引擎：从切点之后当作没发生过（对白 + 本场因此写入的世界）。 |

刻度只给用户句打点。群聊里林夕、陈默每句都打点会变成世界时间轴的赝品，和 Studio 时间线搅在一起。

### 插话：Chat 要做，Agent 也要做，不是同一件事

宪法 §10 群聊写明「用户插话」。只给 Agent 做，Journey D 不成立。

| | **Chat / 扮演 / 群聊** | **Agent（World Builder / 副驾驶）** |
|--|------------------------|-------------------------------------|
| 你在干什么 | 作为在场的人开口 | 给助手改任务、补一句指令 |
| 对方听见吗 | 角色听见，下一句按新话接 | 角色听不见；只有助手改道 |
| 文案 | 「插话」 | 「补充」或生成中直接再发（不对扮演用户讲 Agent） |
| 本切片 | **群聊必做；单角色扮演一并加上**（生成中输入框可发 = 插话） | **同一套刻度 / 暂停 / 撤回控件可共用**；补充指令跟现有世界构建发送走，不新发明「角色插话」 |

v1 不做：插话后让全场自动连辩；暂停后从半句接着生成。

### 回退 = 从那一刻起「没发生过」，含这次对话写出的世界

先前把已确认的世界丢去 Studio 手改，回退就只剩藏几句对白，没有意义。用户说得对。

回退 / 撤回是同一套动作，只是切在哪一句：

- **撤回这条用户消息** = 当作你没发过：这条和后面的 AI 句、思考、提案、由这些句写进世界的改动，都当作没做过。
- **点刻度回退到这条** = 这条用户话还在，它后面的全部当作没做过。

不是两个功能。弹层写清会拿掉几句对白、几张未确认提案、哪些已写入的事件/关系。

**跟着撤的（本场对话、该刻度之后）：**

- 未确认提案 → 丢弃
- 已确认的 **本条消息 apply 出来的** 新建事件 / 关系 → 软删除（现有 `deletedAt`，时间线立刻不见）
- 这些消息里 ingest 的重要聊天 → 失效
- 窗口、检索、角色认知不再读头之后的句

**不能装成没发生过、弹层要明说的：**

- 你后来在 Studio 里又改过的同一条实体（回退会跳过，避免盖掉手改）
- 别的对话已经拿它当亲历在用
- 创建/删除整个世界（`create_project`）
- 扮演 v1 不主动起草的整卡覆盖，若出现且已有更新修订则跳过

今天代码里：确认提案只把消息标成 `applied`，生成的实体 id **只回给前端、没有写回消息**。要让回退真能撤世界，确认时必须把 `entity_id` 记在该条消息上（可写进现有 `proposal` JSON，不必为这个再加一列）。软删除事件/关系的 API 已经有。

Studio 仍是看世界、改手改过的东西的地方，不是回退的日常手续。

### 本切片做到哪

- **必做：** 暂停、插话、撤回最近一条用户话；单角色 + 群聊 + 世界构建线程都可用暂停/插话（语义如上）。
- **刻度条：** 本切片做最小版——对话顶或输入区上方一排用户发送刻度，点开预览 + 回退。弹层列出将当作没发生过的对白、提案、本场写入的事件/关系。不做 Cursor 那种文件 diff 摘要。

## States

### Empty

- 可扮演角色 < 2：说明须再创建角色；不出现残缺群聊线程。
- 已开群聊但还没有消息：说明「他们都在。你先开口，或让他们各说一句。」
- 未选满 2 人：不能开始。

### Loading

- 生成某一位的回复：沿用 SSE；标明正在为谁生成（「林夕正在说…」）。
- 「各说一句」：逐人生成，当前是谁要看得见。
- 可暂停：取消当前思考；半句不入库；未开始的人不再开口。
- 可插话：输入框在思考中仍可发送；发送 = 先暂停再插入用户句。

### Streaming

- 对白可流式；提案仍在该句结束后一次给出。
- 禁止边说边改世界。

### Success

- 每句气泡有角色名（或「读者 / 你扮演的名字」）。
- 关掉再开：人还在、话还在、锚点还在。
- 确认世界变化后：中文说明写了事件还是关系；可去 Studio 看。

### Error

禁止只显示 Error / 500。例如：「没能让陈默开口。对白没写进世界。[重试这一句]」

某人失败不抹掉别人已说的句。世界提案失败与对白失败分开说。

### Retry

- 重试 = 只重生成失败的那一句，不新开群、不重复已成功的句。
- 确认失败：对同一提案重试 apply。

### Cancel

- 关闭选人层 = 不创建线程。
- 暂停 = 取消当前思考，半句不入库。
- 插话 = 先暂停，用户新句进场。
- 撤回 / 回退须先确认弹层：会拿掉哪些对白、哪些提案、哪些本场写入的事件/关系；跳过的手改实体要写明。
- 离开页面：未确认提案保持未确认。
- 从群聊里去掉某人：v1 不做中途改名单（避免日志里出现「当时不在场的人」）。要换人就新开一场。

## Data

| 数据 | 谁写 | 谁读 |
|------|------|------|
| `CreatorChatThread` + `CreatorChatMessage` | 现有消息层 | 日志、窗口、关掉再开、刻度 |
| 对话当前头（见下方存储） | 发送 / 回退 / 撤回 | 窗口、检索、角色听见的范围 |
| `RoleplayThread` | 创建群聊时 | 侧栏、锚点、你是谁 |
| 参与者名单（见下方「需要确认的存储」） | 创建时写入，本场不改 | 谁可以开口、侧栏标题 |
| 每句说话人（见下方） | 落句时 | 气泡名、认知组装、ingest |
| `MemoryAtom` | 该句开口的角色 ingest（扮演模式） | 该角色「调整记忆」；下一轮检索 |
| `ThreadContextState` | 淘汰旧句后滚动摘要（已有） | 仅 prompt |
| `WorldEvent` / `Relationship` | 用户确认后现有 apply-intent | Studio、下一轮亲历 |

用户说的话：全文进日志。v1 **不**把用户句自动归档到某一个 AI 角色的重要聊天（避免「我讨厌海鲜」变成林夕的偏好）。各角色只从**自己说的句**提取重要聊天；问「还记得」仍先查该角色的目录 + 本场日志摘录。

不新建 `World` 表。不把群聊日志当成世界。

### 需要确认的存储（宪法：改模型先报告）

现状：`RoleplayThread.characterAssetId` 只能挂 **一个** AI 角色；`CreatorChatMessage` 只有 `role`（user/assistant），**没有说话人**。群聊若只靠气泡前缀「林夕：」，检索和记忆会错认人。

本切片建议 **不新建表**，只加可空字段（1:1 扮演保持原样）：

1. `RoleplayThread.participantAssetIds Json`：本场 AI 发言名单（2–3 个 id）。`characterAssetId` 仍填名单第一人，供现有列表/复用查询不崩。
2. `CreatorChatMessage.speakerAssetId String?`：这句是谁说的。读者 / 用户卡 / AI 角色。旧的 1:1 消息为 null 时，assistant = `characterAssetId`，user = `userCharacterAssetId` 或读者。
3. `CreatorChatThread.activeHeadMessageId String?`：当前对话头。null = 最新一条。回退/撤回只改这个指针，**不删**消息行。窗口、滚动摘要、检索、ingest 只读头及之前。

若不同意改 Prisma：停在本计划，不写代码。不把名单塞进 `title` 或 `proposal` JSON。

## Cross-module Impact

| 模块 | 变化 |
|------|------|
| Chat 侧栏「角色」 | 「开始群聊」；列表项能看出是群聊（「林夕、陈默」）而不是单人 |
| 扮演气泡 | 每句显示说话人；生成中显示正在为谁说 |
| 对话刻度 | 单角色扮演、群聊、世界构建共用「用户发送」刻度；回退/撤回共用头指针 |
| 单角色扮演 | 旧线程不自动变群聊；补上生成中插话 + 刻度回退 |
| 世界构建 Chat | 不改抽取引擎；可暂停、可补充、可回退。回退同样撤掉该线程在切点之后 apply 的新建实体 |
| 「调整记忆」 | 群聊里切换「看谁的记忆」或默认看上一句开口的人；不把全场日志铺进去 |
| 检索 / 时间认知 | **按当前开口的那个人** 组装；禁止把林夕的亲历灌进陈默 |
| 世界变化提案 | 复用；事件 `character_ids` 应包含在场相关角色；扮演仍每步确认 |
| 小说导入 / 制作 / 语音热词 | 不动 |

若 Studio 在确认后仍看不到事件：算失败。

## User Control

需要确认：

- 创建 / 修改 `WorldEvent`、`Relationship`（现有扮演围栏）
- 记忆 CONFLICT（现有）

不需要确认：

- 对白本身
- 角色自己说出口的补充性重要聊天

回退 / 撤回需要确认弹层（对白、未确认提案、本场因此写入的事件/关系）。Studio 里后来手改过的实体不在本场回退里静默覆盖。

禁止：

- 自动连聊到停不下来
- 群聊静默写世界
- 把 A 的记忆或锚点后剧情喂给 B
- 用户同时「是」某 AI 发言人（你是谁 与 AI 名单互斥）
- 回退时删除整个世界，或覆盖 Studio 里更新的手改
- 删除 L0 消息行来假装回退（只移头 + 软删除本场写出的实体）

高风险（删世界、改名单中途换人、4 人以上、对话分叉多分支、暂停后从半句 token 接着生成）本切片不做。

## Recovery

- 选人层取消：无线程。
- 暂停：半句不落库，没说的不补。现状 Abort 只断前端流，服务端可能还在跑——本切片要把取消做到停思考、不写消息。
- 插话：先暂停，用户新句成为新刻度。
- 撤回 / 回退：头指针前移；日志仍在；该刻度之后本场 apply 的新建事件/关系软删除；重要聊天失效；未确认提案丢弃。Studio 后手改过的跳过并说明。
- 拒绝提案：世界不变，对白仍在。
- 关掉再开：同一 `threadId` 回来，头指针仍在。

[x] 用户能分清谁在说话；生成中能看出正在为谁说
[x] 林夕的回复只用林夕的锚点认知与检索，不用陈默的亲历
[x] 用户随时插话（生成中也可发）；「让 XX 说」「让他们各说一句」可用；暂停停当前句

[x] 用户发送的消息排成刻度；点某刻度能看见那句话；撤回该句 = 当作没发过；回退到该句 = 该句还在、后面没发生过
[x] 回退后窗口和检索不再用头之后的句；日志仍可展开；本场因此新建的事件/关系从时间线消失；Studio 后手改过的实体跳过并说明
