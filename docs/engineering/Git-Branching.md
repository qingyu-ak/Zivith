# Git 分支与提交

## 三条线

| 分支 | 用途 |
|---|---|
| `main` | 发布新版本。只接收已经在 `develop` 上集成过的发布。 |
| `develop` | 主要开发与合并。功能分支从这里拉出，做完后合并回来。 |
| `feat/<短名>` 或 `fix/<短名>` | 一个功能需求，或一个缺陷，单独一条分支。 |

不在 `main` 或 `develop` 上直接改功能、修缺陷。

## 提交

- 说明写清为什么改，而不只列文件名。
- 一个提交只包含一件事。
- 不提交密钥、本地数据库、向量库、`.next` 等构建缓存。
- 未要求时不推送到远端，不把 `develop` 合并进 `main`。

## 现状

当前已发布线是 `main`。集成线建立为 `develop`（与当时的 `zcode` 尖端一致）。之后的新功能从 `develop` 开分支。`zcode` 保留为既有历史，不再当作新功能的默认起点。
